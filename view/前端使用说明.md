# Review Writer 前端使用说明

## 启动

首次使用时，在项目根目录创建并安装工作流环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

随后始终使用该环境启动前端：

```powershell
.\.venv\Scripts\python.exe view\serve_review_dashboard.py --review-root . --host 127.0.0.1 --port 8765
```

浏览器打开：

```text
使用当前部署地址访问；本地默认地址为 http://127.0.0.1:8765，局域网或线上部署请使用实际域名/IP。
```

## 页面

- `Library`：论文入库与 metadata 审核，查看 PDF、MinerU Markdown 和结构化元信息。
- `Discovery`：主题检索结果审核，删除不相关关键词和论文，确认后生成 `selected_discovery_results.json`。
- `Matrix`：查看文献矩阵、逐篇阅读总结、大纲候选和矩阵生成报告。
- `Blueprint`：查看章节任务书，检查每章写作目标、分配文献、段落计划和图表需求。
- `Sections`：查看分章节草稿、章节任务 JSON、章节写作报告和候选图列表。
- `Figures`：检查候选图是否已定位源图、是否完成统一风格重绘，以及是否仍需人工确认。
- `Draft`：查看和编辑合并润色后的初稿，查看 merge report 和 remaining issues。
- `Final`：查看终稿、全文审查报告和 release report，作为发布前最后检查入口。

## 人工检查顺序

```text
Library -> Discovery -> Matrix -> Blueprint -> Sections -> Figures -> Draft -> Final
```

写作前准备只需要使用 `Library`。正式综述任务从 `Discovery` 开始，后续页面都基于同一个 `review-projects/<project_id>` 展示对应阶段产物。

## 持久工作流状态

服务启动后会在工作区的 `.review-writer/workflow.sqlite3` 建立本地状态库。该数据库只保存：

- 阶段运行、人工放行和失败状态；
- 文件的 SHA-256 版本、当前版本指针和生成阶段；
- 输出文件与输入文件之间的版本依赖；
- 批量 AI 重绘的进度、错误和可恢复位置。

PDF、Markdown、PNG、SVG、DOCX 等正文产物仍保存在原来的
`review-projects/<project_id>/<stage>` 目录中。数据库不会替换或移动这些文件。

新生成的 handoff JSON 使用内容哈希判断新旧；旧项目中没有版本快照的 handoff
仍会按原有文件时间规则工作，并在下一次成功执行相应阶段后自动升级。

可通过以下只读接口检查某个项目的当前阶段、产物版本和依赖关系：

```text
GET /api/project/<project_id>/workflow-state
```

## Prefect 工作流编排

当前可执行的阶段任务和“全部 AI 重绘”批处理由 Prefect 3 编排：

- 每次执行都会生成独立的 Prefect flow run 和 task run；
- 阶段执行失败、完成和 Prefect 运行 ID 会同步写入
  `.review-writer/workflow.sqlite3`；
- HTTP 429、500、502、503、504、连接中断和超时会自动重试一次；
- 400、401、403、404、校验错误等确定性问题不会盲目重试；
- 全部 AI 重绘仍按现有逻辑逐张执行，进度和停止状态继续持久化；
- Prefect 结果、日志索引和本地服务数据库统一保存在
  `.review-writer/prefect/`，不会写入项目产物目录。

两套数据库的职责不同：

- `.review-writer/workflow.sqlite3` 是项目业务真相源，保存阶段状态、产物版本、
  文件依赖和可恢复任务进度；
- `.review-writer/prefect/prefect.db` 是编排运行记录，保存 flow/task 的调度、
  日志和运行状态。

默认情况下，前端会按需启动 Prefect 临时本地服务，不需要额外守护进程。
如需持续打开 Prefect UI，可在两个 PowerShell 窗口中分别运行：

```powershell
# 窗口 1：启动持久 Prefect 服务与 UI
$env:PREFECT_HOME=(Resolve-Path '.review-writer\prefect').Path
.\.venv\Scripts\prefect.exe server start --host 127.0.0.1 --port 4200
```

```powershell
# 窗口 2：让 Review Writer 使用该 Prefect 服务
$env:PREFECT_API_URL='http://127.0.0.1:4200/api'
.\.venv\Scripts\python.exe view\serve_review_dashboard.py --review-root . --host 127.0.0.1 --port 8765
```

Prefect UI 地址为 `http://127.0.0.1:4200`。当前执行器设计为前端进程内的
本地 runner；Prefect 服务负责记录与编排，不应把任务单独发送到远程 worker。
